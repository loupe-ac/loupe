# Highlights

Rule 11 of `../SKILL.md`. Read this before you call `document_highlight`. If that tool is not among yours, the instance has highlighting off and none of this applies.

Where it is on, use it. On a long document, the place where the reviewer starts to read is most of what you control. The tool tints the passages you name, so that the reviewer reads them first. Examples are the sections you most want a decision on, the paragraph you are least sure of, and the change this version turns on. A highlight has no body to reply to, so it is no comment. Anything you want to *say* about a passage still goes in a reply on the reviewer's own thread.

Quote the passage **as it reads in rendered prose**, not as your Markdown source. `**must**` matches nothing, and `must` matches. Keep each quote inside one paragraph or list item, because the matched text has line breaks at block boundaries. Every call replaces the whole set. Pass the full list each time, and an empty list to clear it.

Highlights belong to the version that is current when you call. `document_revise` does not carry them forward, so set them again after a revision, on the text you just wrote. Use only a few. A document where everything is marked has nothing marked.
